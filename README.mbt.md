# pi-web-shell

[pi](https://github.com/earendil-works/pi-mono) 的独立复刻：一个 MoonBit 实现的
agent 内核，加一个服务器渲染的 Web UI，交付形态是单个 native 二进制。

```
core/      纯逻辑：消息模型、DeepSeek 编解码、agent 状态机、会话树、工具、压缩
platform/  native 实现：HTTP/SSE、文件系统、进程、script
agent/     驱动：把状态机接到模型与工具
html/      HTML DSL、转义、渲染、Patch
server/    HTTP 路由 + SSE 广播
ui/        可执行：agent + server + Web UI 合一（交付形态）
pi/ cli/   可执行：命令行跑一次完整 turn / 打一次真实 API
verify/    可执行：拿真实会话全量跑往返验证
scriptcheck/ 可执行：编译并运行内置的 script 程序
harness/   Node 脚本：用 pi 当 oracle 生成 fixture、真实浏览器验收
docs/adr/  架构决策记录：被否决过的方案与理由是承重的，不该被重新讨论
```

**一条硬约束**：`core/` 不许碰 IO，必须能编译到**每一个**后端。
`.githooks/pre-commit` 会跑 `moon check -p core --target js` 和 `--target wasm-gc`；
这两条失败就说明有平台代码渗进了核心逻辑。约束靠编译器执行，不靠自觉。

## 运行

```bash
moon run ui                          # → http://127.0.0.1:8790
moon run ui -- --continue            # 继续本目录最近写入的会话
moon run ui -- --resume <id|path>    # 打开指定会话
moon run ui -- --port 9000 --store ~/.pi-mb/sessions
moon run ui -- --no-picker           # 侧边栏不放「Add workspace」，只留路径输入
moon run ui -- --max-cost 0.10 --max-rounds 30 --max-seconds 1800
moon run pi -- "prompt"              # 命令行跑一次完整 turn
moon run verify                      # 全量会话往返验证
moon run scriptcheck                 # 编译并运行内置 script
```

API key 的取法有优先级：`DEEPSEEK_API_KEY` > 设置面板存的 key > pi 的凭据库
（`~/.pi/agent/auth.json`）。都没有也能启动 —— 页面照常起来，左下角的设置面板让人现场填。

每轮的上限同样是三层：flag > 设置面板 > 内置默认（200 次调用 / $1 / 1800s）。默认值取自
2,280 个真实 turn（中位花费 $0.004、p90 $0.036、最贵 $0.295、最长 165 次调用），拦的是
「一个不该发生的 turn」，不是「一个大 turn」。三个上限是三个维度：调用数看得见打转，
钱看得见一次昂贵调用，时间看得见两者都看不见的那种卡住 —— 状态行会说明是哪个守卫触发的。

## 服务器渲染，不是单页应用

服务器是文档唯一的写者。浏览器端只有**不到 100 行 JS**，它知道五件事：怎么应用一个 patch、
怎么发一条 prompt、`data-session` 被点击时打开那个会话、带另一个会话标签的帧不属于本页、
以及设置面板的表单是发出去而不是跳转。对话长什么样完全由服务器决定，所以客户端和服务器之间
没有「状态不一致」这种失败模式。

```
GET  /         整页（含已有对话与侧边栏）
GET  /events   SSE，推 HTML 片段
POST /prompt /session /abort /workspace /workspace/pick /new /more /job/kill
POST /settings/key /settings/skills /settings/limits /model
```

**首帧是「可变区域的快照」**，不是整页。这条曾经写错过：首帧发整页、客户端又用 `outerHTML`
替换 `#transcript`，浏览器把整个文档的片段塞进 body，输入框和状态行都被换成新节点而 JS 里
捕获的还是旧节点 —— **页面看起来正常、输入框却永久失效**，而所有字节断言照旧通过。所以
`server/http_test.mbt` 断言首帧不能出现 `<html`，`harness/ui-browser-check.mjs` 再用**真实的
headless Chrome** 确认 DOM 没被嵌套、监听挂在屏上那个节点。后者是唯一能看见这类问题的地方。

**转义是唯一真正的风险**（输入是模型输出和文件内容）：`Text` 节点永远转义，`Raw` 是唯一
逃生口且只用于 markdown 渲染器的输出。`html/escape_test.mbt` 有四个专门的注入测试。

**标签是一个类型，不是字符串**（`el(Div, …)`，见 ADR-0004）。这是为了堵住 `html/` 这层
interface 上唯一编译期查不到的东西：`el("dvi", …)` 曾经编译通过、测试全过，而客户端对找不到
目标的 patch 是**静默丢弃**的 —— 拼错一个外层标签 = 一个再也不会更新的区域。不用「每个标签
一个函数」（`div(...)`、`i(...)`）是因为标签名是普通小写标识符，**局部变量会遮蔽它**：
`for i in 0..<n` 在渲染 `<i>` 的文件里直接编译失败，而树里已有 10 处这种命名。枚举构造器
住在类型命名空间里，遮蔽不到。`Tag::is_void` 不是穷尽的（33 个里 30 个答 false），属性仍是
字符串 —— 属性拼错是可见的，标签拼错不是，所以只治了后者。

## 一次 turn 在屏幕上长什么样

**必须一直有东西在动。** 这是用户实测出来的：一次提问可能跑 19 次模型调用、25 次工具调用，
而页面当时只推流正文 —— 模型大部分时间在思考，几分钟里屏幕一片空白，看起来就是卡死。现在推
三样：正文、**思考**（默认只露最后三行）、**每个工具**（从开始跑的那一刻出现，带自己的计时，
`data-since` + 客户端 `tick()`，不靠服务器每秒发帧）。

- **流式期间不渲染 markdown**，每个 delta 只更新累积文本，turn 结束时一次性替换成渲染好的
  版本。半截的 `**bo` 渲染出来是错的，而且每来一个 delta 重渲染累积文本是 O(n²)。
- **按大小批处理之外还有一个 250ms 冲刷节拍**：容器在第一个 delta 到达时插进 DOM，而文本要
  攒够阈值才发第一帧，于是流式期间点开是**空白**。节拍把「最多滞后」从若干字符改成 250ms。
- **跑完的工具随手收进折叠**，规则只有一条：最新完成的那个留在外面。一轮的高度否则随工具数
  线性增长。移动由**浏览器**做（补丁协议里没有「移动」），服务器只说哪个块收进哪个折叠。
  实测 4 次调用的一轮：**96px 被收起来**，每多一个工具再多收一份。
- **一轮结束后只留答案**：中间过程（推理、工具、模型动手前说的话）收进答案上方一个
  `<details class="work">`。所谓「最终输出」是**最后一个 `Plain(Text)`**。
- **运行中的 turn 必须能被加入**：中途连上或刷新的人拿到的快照，id 必须是流还在写的那些。
  这条对「已开始、未报告」的工具曾经是破的（result 不是可选的，表示不了它），于是工具结束时
  那条 replace 被客户端静默丢弃，结果永远不出现而字节断言全过。现在它是独立的 `RunningTool`
  分支，验收里有一条：在 `/bin/sleep 20` 跑到 4 秒时刷新，断言运行块仍在、`since` 未变、
  结果落进同一个块。
- **会话之间的切换只是换看的那个**：每个打开的会话有自己的 turn 槽位，切走不打断任何人。
  侧边栏给正在跑的会话打点，看别的会话时状态行补一句 `· N other session(s) running`。

**打开会话默认落在最新处。** 长对话是从结尾读的，而初次加载时 `scrollY = 0`，所以原来的
「贴底才跟随」判断在那一刻必然为假，长会话一定停在最老的内容上。现在：**加载或切换**无条件
落到底；**流式追加**只在读者本来就在底部附近时跟随；**重连**保留读者的位置。

**会话标题钉在顶部**，和侧边栏那一行用**同一个文案规则**（`session_label` + `display_label`：
读者起的名字 → 第一条提问 → 「New session」）。两处对同一个会话给两个名字，会让人怀疑哪个
才对。原先顶上那条信息条拆开搬走了：模型和数字跟着输入框走，因为它们是**下一条消息**的属性；
只有「我是谁」需要一直看得见。

## 会话、工作区、侧边栏

**会话可以命名**：输入框里打 `/name <文字>`（单独打是查看，不会清空）。名字写成 session 格式
里本来就有的 `session_info` 条目，所以跟着日志走，重启后还在，pi 自己也读得到。**turn 运行中
拒绝改名** —— 那时 turn 正按自己的 leaf 追加条目，再塞一条会挂在过期的 parent 上，落到没人走
的分支里。命令只拦截 `/name` 一个：把每个 `/x` 都当命令会悄悄吞掉真正的消息（路径、除法、正则）。

**侧边栏列出所有工作区**，不只是当前目录。会话行正好一行高：标签在左、时间在右，指针停上去
时时间让位给改名与删除（触屏常驻）。**当前会话**用三样东西同时标出：左侧竖条、强调色底、加粗
名字 —— 底不能单独承担，任何「一眼看得见」的底色都会把时间压到 4.5:1 以下，所以底色取 `.12`
而时间改用深一档的 `--muted-strong`（4.66 → 5.02）。每个工作区最多列 10 个会话，多出来的折成
「Show N more」，**上限是为了打开页面不重放整个 store**，所以它落在渲染那层而不是 store 那层。
点开别的目录里的会话会**把 agent 搬过去**。

侧边栏最上面一行可以**添加工作区**，只有一种方式：能弹选择框的宿主机上是一个按钮（macOS 的
`choose folder`，由服务器进程调起 —— 浏览器给不了绝对路径，只有 host 能给），弹不出的宿主机
上是一个路径输入框。**按能力二选一，不是两个入口并排**：知道路径的人在选择框旁边多看到一个
框，只会想「这两个有什么区别」。一个还没有任何会话的目录也是工作区（此前由「store 里有会话」
推断，于是刚添加、还没用过的项目会消失）；工作区记在自己的 `workspace.json` 里，删掉目录就
忘记了它，不会出现「注册表和磁盘不一致」。

工作区的身份（cwd）**从会话 header 读，而不是从目录名反解**：编码把分隔符都换成 `-`，
`--a-b--` 既可能是 `a/b` 也可能是单个目录 `a-b`，猜错就把 agent 搬到一个不存在的地方。

**删掉会话后的「Undo」5 秒后自己消失** —— 那是善意而不是控件，读者已经做完决定。实现的规矩是
「新鲜度是状态的一部分」：删除时把时间戳记下来，渲染和**执行**都问同一个 `still_undoable`，
所以一个挂着很久的标签页重放这个 POST 不会凭空恢复一份被有意删掉的会话。

## 设置面板、工作区指令、skill

页面左下角的 `settings` 是一个原生 `<details>`，位置在一个**不会被 patch 的区域**里，所以一轮
turn 刷新多少次都不会动它；面板向上展开，宽度限于侧边栏那一列（往右铺满会盖住输入框，那是
读者手放着的地方）。它装什么由一个问题决定：**运行中的进程能不能兑现它？** 能兑现的才可改 ——
一个看起来能改的表单只是在撒谎。可改四件：**turn limits**（每轮调用数与花费上限）、**api key**
（只回指纹 `sk-4…2e36`，key 本身永远不回传浏览器）、**skills**（整份提交）、**instructions**
（工作区 `AGENTS.md` 的预览 + 一份后备文本）。其余（模型、监听地址、store 路径）只展示。

两种优先级的**方向是相反的，而且都是刻意的**：key 是**环境变量 > 面板**，因为 `DEEPSEEK_API_KEY`
是读者正看着的 shell 里设的，几个月前在浏览器里存过一次的值不该悄悄压过它；上限是
**flag > 面板 > 默认**，因为 `--max-cost 0.10` 本身就是这次运行敲下的硬帽，让存过的五美元覆盖
它等于把安全边界变成建议。共同点是：意外的那一种要**说出来** —— flag 钉住的那一项在面板里只读，
保存时明确回一句「已保存，但 `--max-cost` 仍然生效」。默认值是 placeholder 不是 value：空 =
没有意见，把 200 填进框里就把它固化成了「读者设的 200」。

三处坑，都是**浏览器验收抓不到的类别里最贵的**（页面看起来正常、按钮也有反应）：

- **表单永远带一个隐藏字段**（`skills=1`、`agents=1`）。全不勾时浏览器提交空 body，而空 body
  与「这不是本面板发的请求」无法区分 —— 没有它，关掉最后一个 skill 就成了面板唯一做不到的编辑。
- **提交后只替换 `settings-body`，不替换整个 `<details>`** —— 展开状态是浏览器自己的，替换外层
  节点会把读者正开着的面板关掉。请求体用 form-encoded，服务端**用实际生效的状态重渲染**再广播。
- **「清除 key」是它自己的表单**。提交按钮的 name 只在它是 submitter 时才进表单数据，而
  `new FormData(form)` 根本不含提交按钮 —— 共用一个表单的话，清除会发一个空的 `key`，被当成
  「什么都没存」，而且把「现在用的其实是哪个」那句话悄悄吞掉。

**工作区指令**（`AGENTS.md`）只有两条规则：工作区有就用它，没有就用设置里那份**后备**。
后备是**二选一而不是追加** —— 仓库自己的文件才是「在这个仓库里怎么干活」的更具体的权威，两份
拼在一起只会让读者去猜哪句话赢了；后备存在 `~/.pi-mb/settings.json`，**跟着人而不是跟着仓库**，
所以「我一贯的偏好」放在那里是诚实的，不用提交进别人的 checkout。**只读工作区根目录那一个文件，
不向上走**：往上遍历是这个设计开始变贵的地方（哪些目录算数、两个都有怎么办、仓库外面的算不算），
而且会让 prompt 的内容取决于 checkout 恰好躺在哪里。**每轮重读，不缓存** —— 换来的是改完下一轮
就生效，而缓存恰好会让这件事不发生。**按磁盘上的原样发送**，只用首尾空白判断它说没说话：把仓库
里的文件改写一遍再塞进 prompt，是那种会让读者从此不信任每一个 diff 的悄悄编辑。

**skill** 从工作区与全局发现，按名字记账，所以同名两份一起生效、重装到别处也不失效；已经不在
磁盘上但仍处于关闭状态的名字照样列出来并标注 `no file found`，否则关掉又删掉的 skill 就再也
开不回来。

## 用量与上下文

**输入框下方那排数字说清整个会话**（口径照 pi 的 footer）：token 进出、cache 读、总花费、
上下文占用；模型下拉框在这一行上。cache chip 同时给出**缓存命中率**
（`cache 12.3k · 87% hit` = `cache_read / (input + cache_read + cache_write)`）。部分命中
**绝不四舍五入成 100%**：整数位会读成满命中时自动补小数（`99.9`、`99.95`、`99.998`…），用
整数运算移植 dsh 的 `formatCacheHitPercent`，保证各后端一致。数字来自日志，所以重启前后一致，
而且**已被压缩替代的那些调用仍然计入** —— 钱已经花了。

**每一轮的回答结尾带一行本轮用量**：同一批数字，但按「轮」给。会话累计会把冷启动和压缩摊平，
看不出某一轮是不是把前缀缓存打掉了；本轮命中率才是读者能据以行动的数字。

**上下文占用是锚定出来的，不是估出来的。** 它是唯一会影响「接下来发生什么」的数字 —— 和压缩
阈值比较，接近时 chip 变红。纯启发式（字符数 ÷ 4）在两处是错的，都是拿真实会话量出来的：
平均只有 provider 真实计费的 **83%**，而且**完全没算固定开销**（系统提示 + 7 个工具 schema
≈ **1,314 token**，每个请求都有）—— 一句 `hi` 的对话因此显示 `~10 tokens` 而真实请求是
~1,300。所以改成锚定：**provider 报的 prompt 大小是已知事实**，只有锚点之后新增的部分才估：

```
next ≈ 上次真实 prompt_tokens + estimate(此后新增内容)
```

同一批会话上 **平均相对误差 17% → 0.2%**（7,510 个样本）。压缩阈值也用这个数：阈值是硬边界，
拿低 20% 的数去比会**压缩得太晚**，而太晚的代价是请求直接超窗被拒。tooltip 会说明这一眼是
`measured` 还是 `estimated`。

**这排数字按「每次模型调用」更新，不是按「每轮」。** 一次 19 次调用的轮次里，读者否则一直盯着
上一轮的旧数字直到整轮结束 —— 而那正是他最想知道「这轮花了多少、窗口还剩多少」的时候。
driver 每写一次日志就报一次（`on_commit`），把**日志当时的样子**交出去。代价是每次提交都重算
chips，而 context chip 要算固定开销，于是顺带重读一次 `AGENTS.md`（一轮几次，每次毫秒级）。
补丁只发给**正在显示这个会话**的浏览器。分工上有一处刻意的分裂：`Runner::session`（transcript
用的）**永远不含正在跑的那一轮**（两处都画就会画两遍），`Runner::in_flight_session` 才是
「日志现在长什么样」，给那排数字和失败路径用。

## 工具

七个工具：`bash`、`read`、`write`、`edit`、`glob`、`grep`、`note`。描述与参数名照抄 pi 的
定义 —— 那是调过的提示文本，照抄既让模型看到同一个工具，也让两边可对拍。

**`script`：跑一段 MoonBit 程序，只拿回它打印的东西。** 另外两条「一步做很多事」的路子
（`bash`、一长串 `read`/`grep`）都受同一件事限制：每一步都要回到对话里。script 把循环放进
程序 —— 一次调用里搜索、过滤、聚合、编辑，交回一份 digest 而不是它为了产出 digest 读过的
原始输出。两种用法：`name` 跑内置脚本，`source` 跑自己的程序。

内置四个（模型只传参数，不必写代码）：

| | 做什么 | 实测 |
|---|---|---|
| `@builtin/check` `[pkg]` | 跑 `moon check --output-json`，按文件聚合错误，只留首行消息 | 40 个错误 **21,336B → 2,028B（10.5×）**；干净时一行 |
| `@builtin/test` `[pkg\|file]` | 跑 `moon test`，只报失败，长值截断 | 失败输出里同一段 400 字符的值会打印三遍（断言、diff 的 `-`、`+`） |
| `@builtin/search` `pattern [dir]` | 正则扫工作区（`moonbitlang/regexp`，VM 引擎，**没有回溯爆炸**） | 跳 `_build`/`.git`/`.mooncakes`；封顶条数 |
| `@builtin/read` `path[:a:b]…` | 批量按行区间读 | 带 `total_lines`/`truncated` 页脚 |

预置库（六个函数，内置脚本与模型自己的程序共用同一份，所以没有两份实现）：
`list`、`read`、`read_lines`、`search`、`read_json`、`edit_text`、`fail`。
`edit_text` 要求 `old` **恰好出现一次**，不是首个匹配 —— 一次含糊的编辑是调用方在猜。

**怎么跑**：staging 在会话级临时目录（工作区之外），`--target-dir` 指向同一个目录 —— **复用
同一个目录就是编译缓存**（实测冷 0.27–0.35s、热 0.03s），不需要另写 build cache 逻辑。
stdout 封顶 **32KB**，`moon` 自己的构建警告不进 digest（它们是说构建的，不是说明结果的 ——
合并进过一次，模型把它当成结果的一部分报回来）。超时走 `exec_managed`，默认 120s。

**安全边界，说清楚不粉饰**：native 的 `script` **与 `bash` 同级信任** —— 能读、能起进程、能改
工作区内的文件。它不是安全改进，**是效率改进**。真沙箱的两条路（wasm + moonrun policy 要
652 行 policy 且 `@fs` 在 wasm 上不可用；JS + `node --permission` 白送沙箱但多一个运行时依赖）
都还没走，理由见「已知限制」。

**内置脚本是字符串里的 MoonBit 源码，没有类型检查器看着它们** —— 一个拼写错误能编译整个项目，
只在模型调用那个脚本时才失败。所以 `moon run scriptcheck` 会编译并运行全部四个，pre-commit
跑它。**它是独立可执行而不是测试**，因为运行它意味着运行 `moon`，而 `moon run` 从 `moon test`
里跑会在构建锁上死锁 —— 实测两次。这条约束决定了它的形状，别把它搬回测试里。

## 后台任务与停止

`bash` 可以留下还在跑的东西（`npm run dev &`），侧栏的 Background 面板让它可见、可停：每行是
一个进程组，带自己的输出尾巴。进程按**会话**记账，超过每会话上限就拒绝新的后台命令并让模型
先清理 —— 「再起一个后台任务」不能变成积累没人数的进程的方式。

一个 turn 是单 worker 串行执行的，所以一个卡住的 turn 会让后面所有请求排队到进程结束。三处
防护：模型两条流（等响应头、等每块数据）各有 **120 秒空闲超时**（按「每次等待」而不是「整个
请求」计时，慢但有进展的响应永远不会被掐断）；turn 自己有三个上限；按停止会把正在跑的工具
一起杀掉（进程组，`subtree` + `kill_pids`）。

**被守卫停下的 turn 会在日志里写下来为什么。** 这是重载后唯一看不到的东西：被成本上限停掉和
正常跑完，在消息里长得一模一样。所以终点追加一条 `custom` 条目
（`{"customType":"turn-outcome","data":{"ending":"round_limit",…}}`）。选 `custom` 而不是往
assistant 消息加字段，是因为消息格式是 pi 的、有别的读者，而「这一轮怎么结束的」是**本 agent
怎么跑的**这一事实；`custom` 也不回放给模型。输出被截断（`finish_reason: length`）同样记 ——
那是最容易被误导的一种：turn 正常结束，别处看不出回答没写完。**正常跑完不写任何东西**。

## 压缩与瘦身

顺序是固定的：**先瘦身，再压缩**。

| | 瘦身（`core/trim.mbt`） | 压缩（`core/compaction.mbt`） |
|---|---|---|
| 做什么 | 裁掉旧工具输出的中段、清空旧思考 | 把旧历史交给模型总结 |
| 代价 | 免费 | 一次 API 调用 |
| 可逆 | **是**（原始内容还在，重读即可） | 否 |

阈值由模型窗口推导。`deepseek-v4-flash` 的窗口是 1M token，阈值因此是 98 万 —— 日常几乎不会
触发，所以这条链路是用 40k 窗口在测试里验证的，而不是等线上触发。压缩写成一个 `compaction`
entry 带 `first_kept_entry_id`：**被替换的内容仍在文件里**。

**摘要回放必须带 `<summary>` 包装**，而且有个不显眼的前提：**pi-ai 根本不认识
`compactionSummary` 这种消息，喂给它会被静默丢掉**（实测：请求体里那条消息直接消失，不报错）。
所以转换必须发生在请求构造之前（`ContextMessage::to_message`）。包装字符串由
`harness/gen-llm-message-fixtures.mjs` 从 `convertToLlm` 捕获，不是手写的 —— 这正是那种会被
人「顺手改整齐」的字符串。

**瘦身对前缀缓存的净收益只量出来一次，结论是「维持现状」**（细节见性能账）：裁剪省下约
$0.95 的 cache-read，而它改写已发送内容造成的重发约 $0.60，净赚 $0.35。试过「没超过压缩阈值
就不裁剪」的版本，算完是**亏的**，回退了。

## 实测过的性能账

优化都从测量开始，否则很容易在不是瓶颈的地方花力气。

| 路径 | 实测 | 结论 |
|---|---|---|
| 会话数据路径 | 5000 条 entry：20 次 append **12ms**、派生+瘦身 **2ms** | 不需要优化。每次 append 重建索引是 O(n)，但要 5 万条才到拐点 |
| 流式推流 | 一条 700 字回答曾经产生 **13.2MB** SSE | 已修：**13.2MB → 78KB（170×）**。形状是平方而不是「慢」：`SetText` 每帧重发整段累积文本，39KB 的思考 = 599 帧 × 平均 20KB。改成发**增量**后字节线性 |
| 侧边栏刷新 | 20 工作区 × 10 会话 × 64KB：**88–150ms/次**，一轮刷新两次 | 已修：按 `(路径, mtime)` 缓存标签 + 前缀 64KB→16KB：**冷 82ms、之后 17–22ms**。根因是**读+解析整份日志只为找一个可能不存在的名字**：27MB 的 store 里 80% 的耗时是解析而不是读 |
| 大会话整页与切换 | 最大真实会话（92 条、257KB）：`GET /` **13ms / 242KB** | 暂不修。随会话线性增长，触发条件是「单会话超过一两 MB 或几百轮」，那时的修法是「只渲染最近 N 轮 + 加载更早」 |
| **瘦身的前缀缓存账** | 3,500 次调用：不裁剪 prompt 总量是现在的 **1.45×**（省约 339M cache-read = **$0.95**）；被改写的调用 **7%**，多付约 **$0.60** | **净赚 $0.35，维持现状**。「没超阈值就不裁剪」的版本算完净亏 $0.36，回退了 |
| **请求前缀（`request_drift`）** | 每轮报告每次请求与上次的共同前缀、从哪条消息开始不同 | 修的是**量尺**：账单里唯一能靠读日志发现、又确实属于我们的浪费是「把已发过的内容改写一遍再发」，而此前日志只有 `usage`（记了什么）没有「为什么」。`moon run pi` 会把它打出来 |

**瘦身那条的教训值得单记**：裁剪的动机是省 token，而 cache read 也是 token —— 省掉的要跟
改写的代价比过才算数。「不要改写已发送的内容」这条设计意图本身**不是结论**。

**`moon build` 默认是 debug**：同一个 `verify.exe`，debug 5.65s vs release 1.17s（4.8×）。
拿 debug 构建比性能会得出反向结论。

## 已知限制

- **续跑是手动的**。崩溃后重开会话，转写末尾出现一条带两个按钮的通知（Continue / Start
  fresh），而不是服务器自作主张接着跑：turn 被中断时**正在执行的那个工具的结果是未知的** ——
  它可能已经改了文件，也可能还没开始。已完成的 call 可以安全跳过（结果就在日志里），「结果
  未知」的那个不能当成成功也不能当成失败。DBOS 的保证建立在 step 是原子的之上，我们没有。
- **工具执行没有审批**，也**不是沙箱**：`bash`、`write`、`edit`、`script` 直接执行。把一个
  目录加为工作区只是让 agent 在那个 cwd 里跑工具，它仍然能用绝对路径读写任何它有权访问的
  地方。`script` 的 native 执行与 `bash` 同级信任（见「工具」一节）。
- **内置 script 是四个**，且只有 `check`/`test`/`search`/`read`。常用的命令（`git`、`npm`）
  仍是原始文本进对话。
- **工作区指令不向上查找**：只有 session 自己那个 cwd 里的 `AGENTS.md` 算数，上级目录一律
  不读，也没有总字节预算。
- **文件夹选择框只在宿主机有桌面会话时出现**（目前只写了 macOS 的 `osascript`）。SSH、容器、
  非 mac 上只有路径输入框。放在 host 侧而不是浏览器里不是偏好：`showDirectoryPicker` 只给
  不透明的 handle，`webkitdirectory` 只管相对名，而 agent 要的是绝对路径。
- **工作区不能改名或排序**；**会话列表没有搜索**，顺序就是 mtime 倒序 —— 会话一多，「记得
  名字、找不到」就是下一条该修的。
- **「Show more」记在进程里，不落盘**：重启回到 10 个。真要做，该存的地方是浏览器的
  localStorage，不是 store。
- **没有图片**：`Image` 内容会被降级成占位文本；**不做流式渲染 thinking**（思考默认只露最后
  三行，实时渲染成 markdown 等于把读者不该读的文本按「已经在读了」的规格排版）。
- **thinking 档位是进程级的**（`high` 写死在调用处），会话级模型已经是每个会话独立的。
- 单会话广播：所有标签页看同一个会话（这是设计，不是缺陷）。

## 曾经存在过的路线一

最初有第二条路线：复用 pi 内核、只重写界面（pi 扩展 + rabbita 前端）。它跑得起来，但和路线二
并列意味着两边都停在半成品，所以删掉了（见 `baa4416`）。留下的两条结论：**rabbita 的 HTML
DSL 在包外不可用**（`server_side_render` 在 `internal/` 里），**SSE 逐块到达是可依赖的**
（预期间隔 120ms，实测 120/121/121/121/121ms）。
