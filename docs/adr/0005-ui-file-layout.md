# ADR-0005：`ui` 按「这件事属于谁」拆成九个文件

- **状态**：已采纳
- **日期**：2026-09-13
- **相关**：`ui/*.mbt`、`docs/adr/0003-requests-module.md`（请求处理抽成模块）；
  ADR-0007（`ui/` 已经删掉，所以这份 ADR 描述的是一个不存在的目录 —— 它的判据仍然可读，
  产物已经没了）

## 背景

`ui/main.mbt` 到了 2455 行、88 个顶层块。`main()` 本身在 ADR-0003 之后已经只有 169 行，
所以剩下的不是「函数太长」，而是**一个概念一个地方**：找「一轮 turn 怎么跑」要在一个 2455 行的
文件里翻，而它和「命令行怎么解析」「设置面板显示什么」挨在一起。

**本 ADR 就是那次架构评审的「候选 C」的落地**（那次评审不在仓库里，「候选 C」没有可点的去处）。
评审当时诚实地标注了：**这是浅活** —— 换文件不改 interface、不增测试面，
是 navigation 而不是 depth。之所以还做，是因为它是最后一件低风险、可一次做完的事，而且候选 B
（`el` 收标签类型）已经把 `ui/` 的构造调用全部碰过一遍，顺手。

## 决策

**按「这件事属于谁」拆成九个文件，同一个包、同一个可执行文件。** 没有新建包，因此没有
interface 变化、没有 `moon.pkg` 改动、没有可见性调整。

划分的判据是**一个问题**：**这件事属于进程，还是属于一个概念？** 属于进程的（命令行、端口、
task group、生命周期）留在 `main.mbt`；其余各归其位。

| 文件 | 它拥有什么 |
|---|---|
| `main.mbt` | 进程：命令行、端口、task group、生命周期 |
| `session.mbt` | `Runner` / `App` 及其访问器 |
| `cli.mbt` | 启动期：命令行、凭据解析顺序、打开第一个会话 |
| `commands.mbt` | 输入框里那句话是什么意思 |
| `model.mbt` | 一个会话跑在哪个模型上 |
| `settings.mbt` | 设置面板：显示什么、提交改了什么 |
| `sidebar.mbt` | 会话列表与它的两个缓存 |
| `turn.mbt` | 跑一轮 turn，以及说清这一轮发生了什么 |
| `panels.mbt` | 各个区域（信息条、用量、下拉框、两个侧栏、对话） |
| `requests.mbt` | 每条路由「意味着什么」（ADR-0003） |

**新代码往哪放**，按这个顺序问：

1. 它属于**进程**吗（端口、signal、生命周期）？→ `main.mbt`
2. 它属于**一个会话的状态及其访问器**吗？→ `session.mbt`
3. 它是**一条路由的决定**吗？→ `requests.mbt`
4. 它**渲染一个区域**吗？→ `panels.mbt`
5. 否则它是某个功能自己的事 → 哪个文件的名字就是那个功能。

## 理由

### 为什么是同一个包，而不是几个包

拆包会引入循环依赖：`Requests` 需要 `App`，`App` 需要 `Runner`，`panels` 需要两者，而 `main`
需要全部 —— 强行分层就要为每个类型引入公开构造器和 getter，把「谁能动什么」从注释变成 API 表面。
那是一次真正的 interface 变化，而这次要解决的只是「找不到东西」。**同一个包 + 每个文件一个主题**
买到全部 navigation 收益，零 interface 变化。

代价写清楚：**它拦不住任何东西**。`panels.mbt` 里写一个 `hub.broadcast` 编译器不会反对。这条靠
文件头注释和 review，不靠类型。

### 拆分的顺序是算出来的，不是抄的

按 `///|` 分隔符切出 88 个块，每块只属于一个文件。切完做了一次**代码行多重集比对**：

```
original code lines: 1628
new code lines:      1628
LOST: 0    ADDED: 0
```

即除注释外**逐字节相同**。之后 `moon check`、468 个测试、`moon run verify`、真实浏览器验收
全部零改动通过 —— 这三件事一起才说明切在真实的缝上：同包内私有可见，所以"不需要改任何东西"
才是预期的结果，需要改才说明切错了。

### 两处不按「它现在放在哪」切

- **`Runner::dismiss` 留在 `session.mbt`**，虽然它追加日志、而 `set_session_model`（同样追加日志）
  去了 `model.mbt`。判据是：dismiss 是 `Runner` 的一个状态迁移，model 那个功能的**全部意义**就是
  那次写入。所以 `session.mbt` 的文件头写的是「不渲染、不写 socket；唯一写的流是会话自己的日志」，
  而不是更漂亮的「不写任何东西」。
- **`expand_skill_command` 放进 `commands.mbt`**，虽然它按 cwd 读文件、而 `commands.mbt` 里另一个
  函数是纯的。判据是「输入框里那句话是什么意思」这个问题：两个入口答的是同一个问题，只是一个
  需要读文件。文件头把这个不对称写出来了。

## 后果

- `main.mbt` 2455 → 206 行；最大的文件是 `turn.mbt`（495 行、一个 turn 的全部）。
  **这些是当时的数字**：`ui/` 在 ADR-0007 之后暂停投入，行数已经不同（`ui/main.mbt` 现在 225 行）。
- **文件头注释是这次的 interface**。同一个包没有类型来约束「panels 不该 broadcast」，所以每个
  文件开头写清它拥有什么、不拥有什么，以及最容易被放错的那一两件事为什么在别处。
- `ui/app_wbtest.mbt`（1310 行）**没有跟着拆**。它是包级白盒测试、按行为组织，现在仍然能用；
  如果它继续长，按同样的主题拆是自然的下一步，不是这次的一部分。
- 候选 C 到此完成。评审清单上剩下的只有**属性类型化**（这次明确没做：标签拼错静默失效，属性拼错
  可见，所以只治了前者）。
