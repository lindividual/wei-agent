# ADR-0010：会话分叉是「复制一个新文件」；花费从分叉点起算

- **状态**：已采纳（**尚未实现**；本 ADR 记的是决定与验收标准）
- **日期**：2026-09-19
- **相关**：`docs/adr/0009-multi-session-coordination.md`（同会话两个 writer 会 fork 日志；这里刻意做了那个
  操作的一种受控版本）、`core/session_entry.mbt`（`SessionHeader.parent_session`）、
  `core/session_context.mbt`（`leaf_id` / `path_to` / `BranchSummary`）、`core/session_usage.mbt`、
  `agent/driver.mbt`（`plan_repair` / `turn_start_type`）、`macos/README.md`（「浏览 ≠ 打开」「列表的第一行是一颗按钮」）

## 背景

中间栏已经有 `New Session`（列表第一行 + ⌘N），于是右侧栏右上角那个 `+` 是同一件事的第三份拷贝，而这个
位置只够放一个按钮。问题是要放什么。

**「分叉」这件事，文件格式里早就留好了位置，只是没接上**：

| 已有 | 位置 | 现状 |
|---|---|---|
| `parent_session`，注释原文就是 “Set when this session was forked from another” | `SessionHeader` | 建新会话时恒为 `None` |
| `BranchSummary(summary, from_id, timestamp)`、`path_to(leaf_id)`、`leaf_id` | `core/session_context.mbt` | 存在，未使用 |
| `plan_repair(session, close_open_turn:)`，其中 `Abandon` 能关掉半截 turn | `agent/driver.mbt` | 存在，本次必须用 |
| 新会话的落盘规则 `session_file_path(root, cwd, now, id)` | `macos/appffi/app.mbt` | 分叉沿用 |

所以这不是造概念，而是**把预留的那条边接上**。而 ADR-0009 已经记过一次相关的疼：同一份会话被两个 writer
交错写会 fork 历史，并留下「指向一个不存在的父」的条目。分叉功能要做的正是在**受控**条件下产生一条分
支，所以那次的教训直接变成了这一轮的实现要求（见「`repair` 必须跑」）。

## 决策

### 1. 复制式，不是同文件分枝

「分叉」在数据模型里有两种可能：**复制一个新文件**（新 `id` + `parentSession` 指针），或在**同一个文件里**
把 `leaf_id` 指回中间某条（配 `branch_summary`）。选前者。

| | **A. 复制式**（选） | B. 同文件分枝 |
|---|---|---|
| 列表 | 一行 = 一个文件，父行不动 | 一行 = 一个文件，**两种状态要画在同一个文件的两条历史里** |
| 切换 | 现成 | 要在会话**内部**重设 `leaf_id` 并切换 → 客户端第一次出现「会话内的视图状态」，且**必须手动重建转录**（pitfalls 有 285 行的条目） |
| 删除 | 现成 | 危险：删「这个分枝」= 丢掉叶子之后的日志 |
| 改名 / 搜索 / 后台运行 | 现成 | 「同一会话的两个分枝叫什么」没有答案 |
| 误操作代价 | 多了一行，删掉即可 | 一次点击移动当前叶子 = **丢弃之后的整段对话** |
| 费用 | 各算各的 | 同一份日志、同一个累计，两条分枝的账算在一起 |

决定性的一条：**「一行 = 一个文件」是 sidebar / 列表 / 搜索 / 删除 / 后台这一层的地基**，B 要在里面加第
二种状态。A 把复杂度关在一个函数里（复制），B 把复杂度摊到每一个读到会话的地方。

### 2. 复制什么

| 项 | 取值 | 为什么 |
|---|---|---|
| `id` | 新的 `new_entry_id()` | 文件身份 |
| `timestamp` | 当前时间（ISO UTC） | 排序、时间分组 |
| `cwd` | **同父** | 分叉是同一个项目里的分叉；换项目是 `New Session in Folder…` |
| `parent_session` | 父文件的绝对路径 | 血缘，且是列表能说「从哪来」的唯一来源 |
| `version` | `Some(3)` | 同 `fresh_session` |
| 路径 | `session_file_path(root, cwd, now, id)` | 落进同一项目目录、排在最后、id 不撞 |
| body | 父的 `entries` **整份**复制 | 无损、可复现 |
| entry **id** | **一个都不改** | 会话是靠 entry id 被引用的（`Session.index`、`parent_id` 链、工具调用的 `call_id`） |

图片跟着复制：日志里图片是**内联 base64**（`{type:"image", data:…, mimeType:…}`，实测一张 ≈0.5MB），复制
就是复制。

**从内存里那份 `open.session` 复制，不重读文件。** 它就是屏幕上那份（driver 在每个 model call、每个工具
轮之后都把它交回 shell，见 `committed(session)`），所以「读者看到什么就分到什么」；而父正在跑 turn 时去读
文件，有读到半行的风险。代价写在「后果」里。

### 3. `repair` 必须跑，两条原因都不是可选的

复制完之后跑一次 `plan_repair(session, close_open_turn: true)`：

1. **父那半截 turn 关成 `abandoned`**。不关，子会话一打开就是「interrupted turn，继续还是重新开始」——
   那不是一条新会话该有的状态。
2. **补上没有回答的 tool call**。不补，子会话的**第一次请求**会被 provider 拒掉，理由是个 byte offset，
   从界面看就是「模型坏了」。这是这一层最贵的坑，也正是 ADR-0009 那次留在地上的东西。

### 4. 花费从分叉点起算

在子会话的链上写一条 **`Custom(custom_type="fork", data={parent, from})`** 标记，紧跟复制的 entries 之后；
`Session::usage()` 只累计**路径上最后一个 fork 标记之后**的条目。

**为什么是标记而不是别的**：

- **不进转录、不进模型**：`context_messages_of` 对非 `message`/`compaction`/`branch_summary`/`custom_message`
  一律返回空 —— 这个标记和现有的 `turn_start` / `turn_outcome` / note 一样天然隐形。
- **不改文件格式**：不需要新的 header 字段；不认识它的读者只是忽略。
- **单调、无算术**：「标记之后」不做减法，所以不存在基线漂移。
- **分叉的分叉自动对**：路径上最后一个标记就是最近一次分叉点。

**不归零的东西**（否则就是说谎）：

| 数字 | 行为 | 为什么 |
|---|---|---|
| 上下文大小 / 离压缩还有多远 | **继承** | 它计的是「要发出去的那个 prompt 有多大」，而这个 prompt 真的带着父的对话。子会话第一轮**可能立刻压缩**，这是诚实的 |
| 每轮的 model calls / tool calls | 本来就每轮归零 | 属于「这一轮」 |
| `turns`（`SessionUsage.replies`） | **归零** | 和 cost 出自同一个 `SessionUsage`；不归零的话子会话第一行就写着父的轮数 |

两条会被误当成 bug 的，写进文档：子会话的累计花费**不含**父（刻意的）；它也**不会被成本上限卡住**——
`max_rounds` / `max_cost` / `max_seconds` 是**每轮**的界（driver 每轮 `usage = zero()`），不是整条会话的。

### 5. 名字：`(fork) 父名`，字面拼接

- **父名**取父会话**当前显示的那个名字**：读者起的名字 → 第一条问题 → short id。
- **规则就是字面拼接**：`"(fork) " + 父名`。**父名里有什么不管** —— 父名本身是 `(fork) 祖父` 时，子的名字就是
  `(fork) (fork) 祖父`。不剥前缀：剥了会让子会话和父会话**同名**（又回到两条一样的行），而且把「从祖父
  分出来」说成事实，是错的。
- **写成一条 `session_info` 名条目**（走 `Shell::rename` 同一条路）：列表立刻显示、读者**可以改掉**、
  换机器跟着文件走、`log_has_name_entry` 的快速判断照常工作。

### 6. 入口与交互

| 入口 | 内容 |
|---|---|
| 工具栏（右侧栏右上角） | 现在的 `+` 换成 `arrow.triangle.branch`，label `Fork Session`（`.fill` / `.circle` 变体在 macOS 26 **不存在**，只有这个） |
| File 菜单 | `Fork Session`，紧跟 `New Session in Folder…`（它创建东西，属 New 一族；Session 菜单里放的是「在会话之间移动 / 停止」，是另一类动词） |
| 快捷键 | **本轮不给**。⌘N / ⇧⌘N 已占，且「一条命令只占一个键」是这个仓库写下来的纪律 |

- **禁用条件**：屏幕上没有会话（`currentPath` 为空）。
- **分叉后自动切过去**，并在 composer 上给**一行**提示（复用现有 notice 机制），说清「从 X 分出来」「之后
  各走各的，父那边不会同步」。
- **不弹对话框**：不破坏任何东西、可删除、可改名 —— 不值得打断。
- **失败要有话说**：父文件不在 / 写不进去 → `say_error` + 不切走 + **不留半截行**。
- 命令走 `/fork`，和 `NewSession` 一样**不 gate 在 idle 上**：父正在跑 turn 时也允许分叉（换会话本来就不
  排队，而 A 不碰父文件）。

## 理由

**为什么不用 "duplicate" 这个词。** 复制**不是镜像**：分叉之后父子之间没有任何同步，父那边继续长，子那边
继续长，两边都不会看见对方。叫它 duplicate 会让人以为有一个跟得上的副本 —— 那是个不存在的承诺。

**为什么花费要断开。** 一条会话的累计花费回答的是「**这个**对话花了多少」。子会话继承的 entries 已经被父
付过账了，把它算进来等于同一次调用被记两次（在两条会话里各算一遍）。归零之后，「这条会话花了多少」对两
条会话都成立。

**为什么"标记 + 只看标记之后"而不是"记一个基线然后做减法"。** 减法是记忆：基线一旦漂了（中途 compaction、
工具报告用量、恢复会话），错误会累积而且看不出来。标记是单调的：它就在链上，任何读者都能重新算。

## 后果

**变好的部分**

- 分叉之后父子**完全独立**，可以各自跑 turn、各自改文件、各自被删除，不需要任何协调层（这正是 ADR-0009 拒
  绝引入的那一层）。
- 删除、撤销删除、改名、搜索、时间分组、后台运行、切换 —— **全部现成**，一个都不用改，因为仍然是「一行 =
  一个文件」。
- 那 285 行的转录重建坑（pitfalls 第三组）**不用碰**：分叉不改变任何一条会话自己的历史。

**要付的代价**

- **文件大小**。复制是字节级复制：实测本机 store 46 条会话 197MB，最大一条 **30MB**（1636 行）。一次分叉
  可能就是 10–30MB。UI 上不说（读者不关心），但要有数。APFS 的 `clonefile`（写时复制）是这一层现成的化痰
  药，但 `platform/` 没有这个能力，而且把语义押在写时复制上是另一个决定 —— 记下来，不做。
- **同名**。父子复制同一段历史，如果什么都不做，两条行的 label 完全一样。这就是 `(fork) 父名` 的全部理由；
  代价是**深层会叠加**（`(fork) (fork) 祖父`），丑但忠实，读者可以改名。
- **花费的语义分成两半**。「这条会话花了多少」从分叉点起算，而「这份对话有多大」继承 —— 两个数字不再出自
  同一次扫描。这是刻意的，但它意味着**两个数字各自都要有出处可讲**，不能含糊成「用量」。
- **这是第一个「一次新建整个文件」的操作**，所以是第一个真的会遇到「写了一半」的操作。要求是**先完整写完
  文件，再 `say_sessions`**：不然留下的是一条看起来正常、实际少了一半的会话，而列表照常显示它。
- **从内存复制而不是读文件**，所以父正在跑 turn 时分叉，拿到的是「已提交的那一段」，不是文件的当前字节。
  这是刻意的（读者分到的是自己看到的），但要在文档里说清楚。

**实现边界（明确不做）**

- 同文件分枝切换（B 方案）。
- **从某条消息分叉**（转录行上的入口）。数据模型支持（`path_to(leaf_id)`），是天然的下一步，但不是这一轮。
- 树形展示 / 缩进 / 折叠 / 合并 / cherry-pick。
- git 分支与 git worktree 集成（ADR-0009 已论证：git 分支不隔离工作区，worktree 一分支一份、冷启动 20–40s、
  ~100MB）。
- 跨项目分叉（`cwd` 保持父的）。
- 父子同步（分叉是**快照**，见「理由」）。

## 要写进 `docs/macos-pitfalls.md` 的（实现时）

1. **`repair` 不跑**：子会话第一次请求被拒，理由是个 byte offset，看起来像模型坏了。
2. **半截 turn 不关**：子会话一打开就是 interrupted 状态。
3. **先写完再报**：`say_sessions` 早于文件写完，列表里会出现一条缺了一半的会话。
4. **同名两行**：`(fork) ` 前缀是解法，深层会叠加。
5. **大文件**：10–30MB 的一次复制，在 agent 线程上，不要搬到主线程。
