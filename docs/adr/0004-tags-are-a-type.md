# ADR-0004：标签是一个类型（`el(Div, …)`），不是一个字符串

- **状态**：已采纳
- **日期**：2026-09-13
- **相关**：`html/node.mbt`、`html/node_test.mbt`、ADR-0001（不写 VDOM 框架）；
  ADR-0007（`html/` 已经随 Web UI 一起删掉，所以这次改造现在是一份历史）

## 背景

`el` 原本接收一个字符串标签：`el("div", attrs=[...])`。标签是 `html/` 这层 interface 上唯一
编译期无法检查的东西 —— `el("dvi", ...)` 编译通过、测试全过、产出浏览器会静默忽略的标记。

后果比「标签写错」更重：客户端对找不到目标的 patch 是**静默丢弃**的

```
const node = document.getElementById(patch.target);
if (!node) return;
```

所以一个拼错的**外层**标签意味着一个再也不会更新的区域，而所有字节层面的断言照旧通过（服务器
确实发了帧）。这和这个项目历史上最贵的那个 bug 属于同一类失败：页面看起来正常、某个东西永久
失效，而测试看不见。

**本 ADR 就是那次架构评审的「候选 B」的落地**。（那次评审不在仓库里，所以「候选 B」这三个字母没有
可点的去处；ADR-0001 的后果一节也把它记成了这个问题的正确最小解法。）评审当时写明它「只动 `html/`，
不加客户端状态、不加 VDOM」。

## 决策

**`el` 接收 `Tag`，一个 33 个变体的枚举**，写作 `el(Div, attrs=[...], children=[...])`。
`Tag::name` 是标签变成标记的**唯一**地方。

## 理由

### 为什么不是「每个标签一个函数」

这是评审当时没验证的岔路，也是这个 ADR 存在的理由 —— 它看起来最好，但**不能用**。

`div(...)`、`i(...)`、`label(...)` 的写法里，标签名就是一个普通的小写标识符，于是**局部变量会
遮蔽它**。实测（最小复现保留在 `html/node_test.mbt`）：

```
error: Type Mismatch
  out.write_string(i(children=[txt("a")]).render())
                   ───────────┬──────────
                     has type : Int
                     wanted   : function type
```

`i` 是最常见的循环下标，而 `html/render.mbt` 正好要渲染 `<i>`。树里已经有 **10 处**这样的命名
冲突：`i`、`label`、`body`、`head`、`html`、`input`、`meta`、`style`、`summary`、`title` —— 全是
自然的名字，所以这个冲突会被反复重新发现。

### 为什么不是大写函数名

`fn Div(...)` 是**解析错误**：大写名保留给构造器。

### 为什么不是单独一个包

`@tags.div(...)` 需要 `Tag` 的构造器与 `Node` 循环依赖，只能拆成三个包 —— 那是候选 C 的工作量，
不是这一件。

### 为什么枚举是对的

`el(I, ...)` 的构造器住在**类型命名空间**里，局部变量遮蔽不到它（上面那条测试同时钉住了这一点）。
它和被替换掉的字符串一样短，拼错就编译不过，而且映射收敛到一处：

```
error: The type @lindividual/wei/html.Tag does not have the constructor Dvi.
```

顺带修掉一个不诚实的地方：原来的 `is_void_element` 列了 14 个 void 标签，而实际只会产出 3 个
（`br`、`input`、`meta`）—— 一份声称知道比实际需要更多事情的清单。现在 `Tag::is_void` 只列在用的，
因为其余 30 个**类型上就产不出来**。

## 后果

- **标签写错的整类 bug 消失了**，包括它最贵的形态（区域悄悄停止更新）。
- `Tag::name` 是穷尽的，所以新增一个标签而不给它名字**编译不过**。这是这次改造买到的核心保证。
- **`is_void` 不是穷尽的**（有 `_ => false`），这是刻意的：33 个里 30 个答 false，列出来是噪音。
  代价写在注释里 —— 新增一个 void 标签而忘了这里会产出 `<img></img>`，错但**可见**，浏览器验收
  会渲染每一个页面。别把它读成编译期保证。
- **序列化逐字节不变**：`html/` 里 7 处断言精确标记的测试、`moon run verify` 的 0 失败、以及真实
  浏览器验收全部原样通过。
- 346 处构造调用里 **194 处 `el(` 改成枚举构造器**（数字是当时的）；`attr`/`cls`/`txt`/`frag` 的形状没动。
- **属性仍然是字符串**（21 个名字，9 处动态拼进数组）。这次没动：标签是唯一「编译期无法检查、
  且错了会静默失效」的东西，属性拼错是可见的。若将来要治，形状会不一样。
- 候选 C（拆 `ui/`）没受影响，而且现在更便宜了：`ui/main.mbt` 里只有 6 处 `@html.el(` 需要跨包构造器。
