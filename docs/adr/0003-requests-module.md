# ADR-0003：请求处理是 `ui` 里的一个模块，不是 `main` 里的闭包

- **状态**：已采纳
- **日期**：2026-09-13
- **相关**：`ui/requests.mbt`、`ui/requests_wbtest.mbt`、`ui/main.mbt`、`server/http.mbt`

## 背景

`main` 原本是 433 行，里面装着九个闭包：一个路由表 `@server.Routes`，每个字段一个 handler，
handler 里写着「这次请求意味着什么」的全部判断 —— 拒绝一个改名的三种理由、拒绝一个模型切换的
三种理由、一个设置表单解码后做什么、一次 abort 该刷新什么、一次显示切换打开哪个会话。

`main` **不能被测试**：它解析命令行、绑端口、然后阻塞。写在它里面的闭包没有 interface，任何东西
都跨不过那道缝去检查它。

代价不是理论上的，是已经发生的：

- 读者见到的**六条拒绝信息里，五条只出现在 `ui/main.mbt` 这一个文件里，而它是唯一没有测试的文件**
  （`not a directory` 是例外，浏览器验收里有断言）；
- 模型下拉框「turn 结束后不解锁」这个 bug，**没有任何测试失败** —— 那个状态迁移没有 interface
  可以断言，是靠重读流程找出来的；
- `/model` 的守卫被写了两遍（命令分支 + 下拉框路由），而且**已经不一致**：下拉框在拒绝后会把控件
  放回原位，命令路径不会，所以打错一次 `/model` 会给下一次点击留下一个和实际不符的 `<select>`。

## 决策

**路由的「决定什么」放进 `ui/requests.mbt`，`main` 只留进程级的东西**：命令行、端口、task group、
生命周期。

界线的判据是「这件事属于进程还是属于模块」：

- 起一个 turn 需要一个 `TaskGroup`（泛型、带 source location）→ 属于进程 → **作为回调参数传进去**，
  而不是被 `Requests` 知道；
- 显示切换要按到达顺序执行 → 队列作为参数传入；
- 端口、serve、日志 → 留在 `main`。

**测试跨的 seam 是 `@server.Hub`。** 一条拒绝*就是*一帧：断言广播出去的内容，就是断言浏览器被告知
了什么，而这正是那个行为的全部。所以 handler **直接广播**，而不是返回「该广播什么」的描述 —— 后者
会把「决定」和「发送」拆成两处，正是当初遗漏模型下拉框的那种分工。`Requests` 的 `app` 字段就是测试
的注入点：测试塞一个 `test_app_in` 造的 `App`（真 hub、真 registry），然后像标签页一样 subscribe。

## 理由

- **interface 就是测试面。** 抽出来之后，六条拒绝信息全部有断言，而且第一次就抓到了上面那处
  **已经漂移的重复**：两条路径现在共用一个 `change_model`，各自有测试。这是「深」带来的直接回报 ——
  两个调用点、一处实现、一处修复。
- **`main` 缩短到 161 行**（从 433），而且剩下的每一行都是「启动这个进程」而不是「一次请求意味着
  什么」。它现在读起来是装配，不是逻辑。
- 纯拆文件（把 433 行整块搬到别的文件）不会带来这些：interface 没变、测试面没多。改变的是
  **谁拥有这些决定**。

## 后果

- 加一条路由 = 在 `Requests` 上加一个方法 + 在 `routes()` 里连一行；决定写在方法里，能被测。
- `page()` 和 `regions()` 必须留在同一个模块里：它们是同一份状态的两种渲染，而把它们分开的失败
  模式是**静默的** —— 某个区域在首帧里存在、在快照里没有，浏览器一重连就失效。有一条测试专门钉
  这件事（每个被 replace 的 target 的 id 必须在 `page()` 里出现）。
- `regions()` 是 `async`，所以 `Requests::routes` 的 URL → 决定的映射本身只由
  `server/http_test.mbt` 覆盖（真 socket），方法的**行为**由 `ui/requests_wbtest.mbt` 覆盖。
  两层各自覆盖自己那一半，没有重复。
- 进程级的东西因此只有一处：`log` 只在 `main` 里（见 ADR-0002）。
